### 1. 맵 제작과 편집 도구

잠수맵과 초밥집의 공간을 구성하고 지형·환경 오브젝트를 배치했습니다. 배치 결과를 저장하고 다시 편집할 수 있도록 팀원과 함께 ImGui 기반 편집 기능을 구현했습니다.

<!-- GIF 추가 예정: 잠수맵 탐색 / 초밥집 맵 / 편집 도구 조작 -->

#### 오브젝트 배치와 속성 편집

패널에서 오브젝트를 생성해 레이어에 등록하고, 목록 또는 마우스 피킹으로 편집 대상을 선택합니다. 선택한 오브젝트의 Transform을 통해 위치·회전·크기를 조절합니다. `Show_Obj()`에서는 레이어별 오브젝트 목록을 표시하고 선택·삭제를 처리합니다.

`CFactoryMgr`는 오브젝트 종류별 개수를 관리해 이름에 번호를 붙이고 레이어에 등록합니다. 같은 종류를 여러 개 배치할 때 사용할 이름 생성과 등록 처리를 모았습니다. 본인이 초기 버전을 작성한 뒤 팀원이 함수 분리와 카운터 초기화 기능을 추가했습니다.

#### 맵 저장과 로드

레이어의 오브젝트를 순회하며 **종류 이름·위치·회전·크기**를 JSON으로 저장합니다. 저장 시 이름의 번호 부분을 제외하고, 로드 시 종류에 맞는 오브젝트를 생성해 레이어에 등록한 뒤 Transform을 복원합니다.

공개 샘플에서는 종류마다 반복되는 생성 분기를 줄이고 대표 사례와 데이터 복원 흐름을 남겼습니다.

#### 마우스 피킹

화면의 마우스 좌표를 이용해 월드 공간의 레이를 구하고, 오브젝트의 AABB와 교차하는지 검사합니다. 축별 진입·이탈 구간을 비교하는 Slab 방식으로 교차 여부를 판단하고, 코드에서 계산한 교차 거리 중 가장 가까운 오브젝트를 편집 대상으로 선택합니다.

### 2. 잠수맵 ESC 인벤토리

잠수 중 확인하는 인벤토리 화면을 구성하고, 획득한 물고기 목록의 탐색·선택·버리기를 구현했습니다. 인벤토리 전체의 입력·목록 관리는 `CInventory`, 개별 슬롯의 표시와 마우스 판정은 `CItemSlot`이 담당합니다.

<!-- GIF 추가 예정: ESC 화면 열기 / 스크롤·선택 / 버리기 확인 -->

#### 목록 스크롤과 선택

스크롤 위치로부터 목록의 시작 데이터 인덱스를 계산하고, 미리 생성한 슬롯에 표시할 데이터를 갱신합니다. 선택 항목은 화면상의 슬롯 번호가 아닌 실제 데이터 인덱스로 관리해 목록이 스크롤되어도 선택 대상을 구분합니다.

마우스 휠과 W·S 키로 목록을 탐색하고, 마우스 클릭으로 슬롯을 선택할 수 있습니다. 선택한 항목이 화면을 벗어나면 스크롤 위치를 조정합니다. 렌더링에는 DirectX 9의 **Scissor Rect**를 적용해 슬롯이 목록 영역 밖에 그려지지 않도록 합니다.

#### 버리기 확인과 데이터 갱신

선택한 물고기를 버릴 때는 확인 패널을 표시하고, 확정 입력을 받으면 데이터 매니저의 인벤토리에서 해당 항목을 삭제합니다. 이후 선택 인덱스와 슬롯 선택 표시를 초기화합니다. 확인 패널이 열린 동안에는 목록 탐색 입력을 제한합니다.

### 3. 초밥집 운영

**손님 입장·착석 → 주문 → 반쵸의 조리 → 플레이어 서빙 → 판매 결과 집계**로 이어지는 운영 흐름을 구현했습니다. 운영 데이터는 `CRestaurantMgr`, 손님과 반쵸의 행동은 각 오브젝트가 처리합니다.

<!-- GIF 추가 예정: 손님 입장부터 주문·조리·서빙까지 / 영업 종료 -->

#### 손님과 주문 관리

비어 있는 좌석과 아직 좌석이 배정되지 않은 손님을 찾아 일정 시간 간격으로 연결합니다. 주문 시에는 팀의 메뉴 데이터에서 남은 수량이 있는 초밥을 선택하고 수량을 차감한 뒤, 손님과 초밥 정보를 함께 주문 큐에 넣습니다.

반쵸는 주문 큐에서 다음 주문을 받아 조리를 시작합니다. 조리 시간이 충족되면 완성된 음식 목록에 추가하고 다음 주문을 처리할 수 있는 상태로 돌아갑니다.

#### 음식 수령·서빙과 녹차 연동

팀원이 제작한 초밥집 플레이어에 상호작용 기능을 추가했습니다. 반쵸와 접촉한 상태에서 입력하면 완성된 음식을 받고, 손님에게 전달할 때는 들고 있는 초밥이 주문과 일치하는지 확인합니다. 서빙하거나 음식을 버리면 주문 데이터와 서빙 상태를 초기화합니다.

녹차를 요청한 손님과 상호작용하면 해당 손님의 타이머를 멈추고 녹차 UI를 엽니다. 녹차 제공 중에는 플레이어 입력을 제한하며, 완료 시 손님의 타이머와 플레이어 상태를 다시 연결합니다. 녹차 UI 자체의 전체 구현을 담당했다는 의미는 아닙니다.

#### 영업 종료와 결과

손님 생성이 끝나고 관리 중인 손님이 모두 퇴장하면 영업 종료 이벤트를 보냅니다. 판매 금액·팁과 초밥 종류별 판매 횟수를 관리하고, 가장 많이 판매한 메뉴 정보를 결과 데이터로 반환합니다.

### 4. 초밥집 UI

손님과 반쵸의 현재 데이터를 읽어 운영 상태를 화면에 표시했습니다. UI에 별도의 주문 상태를 만드는 대신, 연결된 오브젝트의 상태와 진행 시간을 기준으로 표시 내용을 갱신합니다.

<!-- GIF 추가 예정: 주문 강조·대기 게이지 / 조리 진행·완료 슬롯 -->

#### 손님 주문과 대기 상태

`CUI_Customer`는 손님의 상태에 따라 녹차 또는 초밥 주문을 표시하고, 대기 시간을 비율로 계산해 게이지에 반영합니다. 플레이어가 들고 있는 음식이 손님의 주문과 같으면 표시 이미지를 바꿔 서빙 대상을 구분합니다. UI 위치는 손님의 위치를 따라 갱신합니다.

#### 반쵸의 조리 진행과 완료 표시

`CUI_Bancho`는 미리 생성한 4개의 슬롯에 완성된 음식과 현재 조리 중인 음식 정보를 표시합니다. 완성된 음식을 먼저 배치하고, 빈 슬롯이 있으면 조리 중인 음식을 추가합니다.

조리 시간의 진행률을 게이지에 반영하고, 완료된 음식은 배경 이미지로 구분합니다. 표시할 데이터가 없는 슬롯은 비활성화합니다.

## 코드 공개 범위

주요 담당 기능과 공동 구현 기능을 보여주는 **10개 클래스의 헤더·소스, 총 20개 파일**을 공개합니다. 팀 공통 엔진과 다른 팀원의 기능을 사용하는 코드이며, 공개한 클래스 전체를 단독 작성했다는 의미는 아닙니다.

`CImGuiMgr`와 `CFactoryMgr`는 공동 구현 범위를 명시하고, `CBancho_Player`는 본인 기여 부분 중심으로 발췌했습니다. `[중략]`으로 표시한 부분과 전체 엔진·리소스·프로젝트 설정이 포함되지 않아 **이 저장소만으로 빌드하거나 실행할 수 없습니다.**

## 제작 목적 및 리소스 출처

본 프로젝트는 게임 클라이언트 개발 학습을 위해 제작한 **비영리 교육용 모작**입니다. 원작 리소스는 학습·교육 목적으로만 사용했으며, 구현 내용과 학습 결과를 포트폴리오로 정리했습니다.

원작은 **데이브 더 다이버(DAVE THE DIVER)**이며, 사용된 원작 이미지·음원 등 리소스의 권리는 각 권리자에게 있습니다. 본 프로젝트는 원작의 공식 프로젝트가 아닙니다.
